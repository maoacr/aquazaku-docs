# M0 — Auth + RBAC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build M0 (Auth + RBAC) of the Aquazaku system: identity, authorization with 4-role matrix + scope model, audit log consultable from UI, BFF pattern, and seed for the first admin.

**Architecture:** Polyrepo with two independent projects — `api/` (Fastify + Drizzle + Postgres + Better-Auth + custom authz module) and `web/` (Next.js App Router BFF). Web never talks directly to api from the browser; all communication goes through `apiServerFetch()` helper server-to-server. Permission matrix is declared in TypeScript, applied in ONE data layer (`scopedQuery`). Audit log is append-only (REVOKE + trigger). All defense-in-depth: skill + helper module + ESLint rule.

**Development approach:** **Incremental with E2E verification per feature boundary.** Each api/ task that produces endpoints must add an E2E test (real HTTP request → expected response) before moving on, not just at the end. Each web/ task that produces UI must be manually verified in a browser before merge. API is also documented in a **Postman/Bruno collection** versioned in the repo, so manual exploration is reproducible and CI-runnable.

**Tech Stack** (stable vigente al 2026-08-19, verificado contra el registro de npm):
- Runtime: Node.js 22 LTS
- api/: Fastify 5.x, Drizzle 0.45.x, Postgres 16, Better-Auth 1.7.x, Zod 4.x, argon2id (`@node-rs/argon2`), Pino 10.x, Resend (prod) / Mailpit (dev), Vitest 4.x + Supertest
- web/: Next.js 16 (App Router), React 19.2, Tailwind, TanStack Table, Vitest 4.x + Testing Library + MSW
- Tests: Vitest with min coverage `authz/` ≥85%, global ≥70%
- API exploration: **Bruno** (open source, files-in-repo, CLI-runnable) as primary; Postman-compatible JSON export

**Entorno local:** ya provisionado (Postgres 16 nativo vía Homebrew, Mailpit, Bruno CLI global). Ver [Entorno local](/empezar/entorno-local/). **No se usa Docker Compose**: Postgres corre como servicio de login y CI usa la imagen `postgres:16`, misma línea de versión.

## Global Constraints

- **Polyrepo:** `api/` y `web/` son repos git independientes, cada uno con su propio `git init` y su propio remote. El repo paraguas (`/Users/mao/code/aquazaku`) los ignora en `.gitignore` — nunca se commitea código desde la raíz
- **Node 22 LTS fijado explícitamente** en ambos repos: `.nvmrc` con `22` + `"engines": { "node": ">=22" }` en `package.json`. Sin esto, cada máquina resuelve una versión distinta
- **Postgres local ya provisionado**: role `aquazaku`, bases `aquazaku_dev` y `aquazaku_test`, extensiones `citext` + `pgcrypto` creadas. Los tests corren contra `aquazaku_test`, nunca contra `aquazaku_dev`
- **Emails en dev van a Mailpit** (`smtp://localhost:1025`, UI en `http://localhost:8025`), nunca a internet. Resend solo en producción
- TypeScript strict mode in both `api/` and `web/`
- All files use 2-space indentation, single quotes, no semicolons (project convention)
- No `Co-Authored-By` in commits (per project AGENTS.md)
- Conventional commits: `feat:`, `fix:`, `chore:`, `test:`, `docs:`
- Every commit must leave the project in a green state (tests + lint + typecheck pass)
- No TODO/PLACEHOLDER comments in shipped code
- All API endpoints require authentication except `/auth/sign-in`, `/auth/forgot-password`, `/auth/reset-password`
- Cookie name: `aquazaku_session`, httpOnly, sameSite=Lax, 7-day expiry with sliding window
- Password hashing: argon2id via Better-Auth, min length 8
- Rate limit: 5 failed login attempts per IP+email per 15 minutes
- Drizzle migrations are explicit SQL, never auto-generated against production
- `audit_log` is append-only: REVOKE UPDATE, DELETE + trigger that rejects mutations
- ESLint rule in web/: bans `fetch()` direct and `localStorage`
- No JWT — sessions live in DB for revocation
- **E2E coverage is mandatory per feature boundary:** every new api/ endpoint gets a real-HTTP E2E test (not just unit) before its task is "done". Every new web/ page gets manually verified in a browser before its task is "done". Unit tests are necessary but not sufficient.
- **API is documented in a versioned Bruno collection** at `api/bruno/aquazaku/` — added in Task 15, updated whenever an endpoint changes

- [x] **Step 1: Write `api/src/db/schema.ts`**

```ts
import { pgTable, uuid, text, timestamp, boolean, jsonb, inet, bigserial, pgEnum, primaryKey, index } from 'drizzle-orm/pg-core'

export const userStatusEnum = pgEnum('user_status', ['active', 'inactive'])
export const auditResultEnum = pgEnum('audit_result', ['ok', 'denied'])

export const users = pgTable('users', {
  id: uuid('id').primaryKey().defaultRandom(),
  email: text('email').notNull().unique(),
  passwordHash: text('password_hash').notNull(),
  name: text('name').notNull(),
  status: userStatusEnum('status').notNull().default('active'),
  mustChangePassword: boolean('must_change_password').notNull().default(true),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
})

export const sessions = pgTable('sessions', {
  id: text('id').primaryKey(),
  userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  roles: text('roles').array().notNull(),
  expiresAt: timestamp('expires_at', { withTimezone: true }).notNull(),
  ip: inet('ip'),
  userAgent: text('user_agent'),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  userIdx: index('sessions_user_idx').on(t.userId),
}))

export const roles = pgTable('roles', {
  name: text('name').primaryKey(),
  description: text('description').notNull(),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
})

export const userRoles = pgTable('user_roles', {
  userId: uuid('user_id').notNull().references(() => users.id, { onDelete: 'cascade' }),
  roleName: text('role_name').notNull().references(() => roles.name),
  grantedAt: timestamp('granted_at', { withTimezone: true }).notNull().defaultNow(),
  grantedBy: uuid('granted_by').references(() => users.id),
}, (t) => ({
  pk: primaryKey({ columns: [t.userId, t.roleName] }),
}))

export const auditLog = pgTable('audit_log', {
```

**Lo que el plan tenía mal, y por qué importaba:**

| Problema | Corrección |
|---|---|
| **El schema no era compatible con Better-Auth 1.7.** El plan ponía `password_hash` en `users`; Better-Auth lo guarda en `accounts`. Faltaban `accounts` y `verifications`, `users.emailVerified`, y `sessions.token` separado de `sessions.id`. Además `accounts.issuer` es requerido desde 1.7 y forma índice único con `accountId` — eso **no está en la doc, sale del código fuente** | Schema reescrito compatible desde el arranque. Sin esto, Task 5 obligaba a rehacer migraciones |
| **`REVOKE ... FROM aquazaku_app` no protegía nada.** Ese rol no existía, y la app se conectaba con `aquazaku`, que es **dueño** de las tablas. A un dueño no se le revoca nada de forma efectiva | Se creó `aquazaku_app` con privilegio mínimo, y `api/` ahora usa dos DSN: `DATABASE_URL` (app) y `DATABASE_MIGRATION_URL` (migraciones). Ver [ADR-0004](/decisiones/0004-audit-log-inmutable/) |
| **Triggers `FOR EACH ROW`.** Un `DELETE` que no matchea ninguna fila jamás los dispara: pasaría en silencio | Se pasaron a `FOR EACH STATEMENT`, y se agregó uno para `TRUNCATE`, que no dispara los de UPDATE/DELETE |
| **`email` era `text`**, pese a que el spec §6 dice `citext` y la extensión ya estaba instalada | `citext` vía `customType` de Drizzle. La migración crea la extensión sola |
| **Step 8 verificaba los triggers a mano en psql.** Una garantía comprobada a mano una vez no es una garantía | 12 tests automáticos que además distinguen **qué capa** frenó cada intento: al rol de app lo para el `GRANT` faltante, al dueño lo para el trigger |
| `env.ts` usaba `z.string().url()` y no contemplaba los dos DSN | Reescrito con Zod 4 (`z.url()`), los dos DSN, transporte de mail y validación cruzada de Resend en producción |

**Decisiones tomadas al implementar:**
- **`audit_log` sin FK a `users`**: si un usuario se borra, su rastro debe sobrevivir. Un log que se borra en cascada no es un log.
- **`sessions.ipAddress` es `text`, no `inet`**: Better-Auth escribe ahí lo que venga en el header. Con `inet`, un proxy mal configurado tira el login abajo.
- **El logger salió a `lib/logger.ts` como función pura.** Sus ramas por `NODE_ENV` son incubribles corriendo bajo un solo entorno. La salida no era bajar el gate de coverage: era extraer la lógica y testearla de verdad.
- **Exclusiones de coverage documentadas**: `server.ts` (entrypoint: testearlo sería testear a Node), `src/test/**` (helpers), `src/db/schema.ts` (declaración sin ramas; lo prueban los tests contra la base real).

```ts
import { eq } from 'drizzle-orm'
import type { SQL, SelectQueryBuilder } from 'drizzle-orm'
import { PERMISSION_MATRIX, type Action, type Resource, type Role } from './matrix'
import type { UserContext } from './can'

export function applicableScopes(
  user: UserContext,
  resource: Resource,
  action: Action,
): string[] {
  const scopes = new Set<string>()
  for (const role of user.roles) {
    for (const rule of PERMISSION_MATRIX[role]) {
      if (rule.resource === resource && rule.action === action) {
        scopes.add(rule.scope)
      }
    }
  }
  return Array.from(scopes)
}

export function scopedQuery<T extends SelectQueryBuilder<any, any, any>>(
  user: UserContext,
  baseQuery: T,
  resource: Resource,
  action: Action,
): T {
  const scopes = applicableScopes(user, resource, action)

  // 'todo' wins: no filter
  if (scopes.includes('todo')) return baseQuery

  let query = baseQuery
  for (const scope of scopes) {
    if (scope === 'propio') {
      // Assumes the table has a `createdBy` column
      query = query.where(eq((query as any)._.table.createdBy, user.id)) as T
    }
    // Other scopes are placeholders for M1+ modules
  }
  return query
}
```

```ts
import type { FastifyReply, FastifyRequest } from 'fastify'
import { eq } from 'drizzle-orm'
import { db } from '@/db/client'
import { sessions, users } from '@/db/schema'
import { can, type UserContext } from './can'
import { emit } from './audit'
import type { Action, Resource, Role } from './matrix'

declare module 'fastify' {
  interface FastifyRequest {
    user?: UserContext
  }
}

export async function requireAuth(
  req: FastifyRequest,
  reply: FastifyReply,
): Promise<void> {
  const sessionId = req.cookies['aquazaku_session']
  if (!sessionId) {
    return reply.code(401).send({ code: 'UNAUTHENTICATED' })
  }

  const [session] = await db
    .select()
    .from(sessions)
    .where(eq(sessions.id, sessionId))
    .limit(1)

  if (!session || session.expiresAt < new Date()) {
    return reply.code(401).send({ code: 'SESSION_EXPIRED' })
  }

  const [user] = await db
    .select()
    .from(users)
    .where(eq(users.id, session.userId))
    .limit(1)

  if (!user || user.status !== 'active') {
    return reply.code(401).send({ code: 'USER_INACTIVE' })
  }

  req.user = {
    id: user.id,
    roles: session.roles as Role[],
  }
}

export function requirePermission(resource: Resource, action: Action) {
  return async (req: FastifyRequest, reply: FastifyReply): Promise<void> => {
    if (!req.user) {
      return reply.code(401).send({ code: 'UNAUTHENTICATED' })
    }

    const allowed = can(req.user, resource, action)
    const requestId = (req.headers['x-request-id'] as string) ?? crypto.randomUUID()

    if (!allowed) {
      await emit({
        userId: req.user.id,
        rolEjercido: req.user.roles,
        action: 'PERMISSION_DENIED',
        resource,
        resourceId: undefined,
        result: 'denied',
        requestId,
        ip: req.ip,
        userAgent: req.headers['user-agent'],
        payload: { attempted_action: action },
      })
      return reply.code(403).send({ code: 'FORBIDDEN', resource, action })
    }

    await emit({
      userId: req.user.id,
      rolEjercido: req.user.roles,
      action: 'PERMISSION_GRANTED',
      resource,
      resourceId: undefined,
      result: 'ok',
      requestId,
      ip: req.ip,
      userAgent: req.headers['user-agent'],
      payload: { attempted_action: action },
    })
  }
}
```

**La decisión de fondo: qué se audita.**

El plan escribía en `audit_log` en **cada permiso concedido** — un INSERT por request autorizado. RN-ACC-04 no pide eso: pide auditar las acciones **sensibles**, y las nombra una por una. Auditar cada lectura tiene dos costos y ningún beneficio: amplificación de escritura por carga de pantalla, y miles de filas de ruido que entierran justo las acciones que hay que poder encontrar. Un log que nadie puede leer no es un control.

Política implementada:

| Caso | Se audita |
|---|---|
| Cualquier acceso **denegado** | Siempre, sin excepción |
| Acción permitida que modifica estado | Sí |
| Lectura pura permitida (`ver`, `operativos`, `financieros`) | No |
| `auditoria:ver` | **Sí** — quién mira la bitácora queda en la bitácora |
| `reportes:descargar_pdf` | **Sí** — lo pide el doc de dominio |

El default es auditar: para dejar algo afuera hay que agregarlo explícitamente a la lista de exentas. Ante la duda, el sistema audita de más. Hay un test que recorre toda la matriz y verifica la invariante.

**La otra decisión: qué pasa si la auditoría falla.**

| Caso | Respuesta | Por qué |
|---|---|---|
| Denegado y no se pudo auditar | 403 igual, error al log | El usuario queda bloqueado, que es lo que protege al sistema |
| Permitido y no se pudo auditar | **500, y la acción NO se ejecuta** | Dejar pasar una acción sensible sin rastro sería incumplir RN-ACC-04 en silencio |

Preferimos un endpoint caído a una acción sensible sin registro. Hay tests con `emit` mockeada que fijan las dos conductas — sin ellos la decisión sería un comentario, no un comportamiento.

**Correcciones al plan:**

| Problema | Corrección |

**El hueco más grande: el plan no auditaba los logins.** Ni los exitosos ni los fallidos.

Un login fallido es la señal de seguridad más básica que existe: una ráfaga contra el mismo email es fuerza bruta, y sin registro no hay forma de verla ni en el momento ni después. Se auditan en nuestro propio plugin, que ya envuelve cada request de Better-Auth y ve URL, body y status. Los fallidos van con `userId: null` — exactamente para lo que Task 4 dejó ese campo nullable.

Se guarda el email del intento y **nunca** la contraseña, ni siquiera la fallida. Hay un test que lo verifica buscando el string en toda la bitácora.

**Bug de dependencia circular, y de los peores.** `better-auth.ts` importaba `COOKIE_SESION` de `authz/middleware.ts`, que importa `auth` de `better-auth.ts`. Al agregar `routes.ts` cambió el orden de evaluación y la constante llegaba `undefined` al construir la config.

El síntoma: Better-Auth caía en su nombre de cookie por defecto. El login respondía **200**, creaba la sesión, devolvía el token en el body — y la cookie salía con otro nombre. Todo "funcionaba" y nadie quedaba logueado. La constante se movió a `auth/cookie.ts`, un módulo que no importa nada.

**Correcciones al plan:**

| Problema | Corrección |
|---|---|
| Borraba la sesión con `req.server.pg.query` — un decorador que no existe — y por `session.id`, cuando la cookie lleva `token.firma` | Delega en `auth.api.signOut`, que invalida la sesión y emite la cookie de borrado con los mismos atributos con que la creó. Una cookie limpiada con otro `path` no borra nada y el usuario se queda logueado creyendo que salió |
| Auditaba la acción como `'LOGOUT'` | `auth:sign-out`, la nomenclatura del dominio |
| `/auth/me` devolvía solo `id` y `roles` | Ahora trae `name`, `email`, `mustChangePassword` (spec §7.2) y los **permisos resueltos**, para que `web/` arme la pantalla en un solo viaje sin replicar la matriz |
| El test E2E insertaba `passwordHash` en `users` — columna que no existe, el password vive en `accounts` | No habría compilado. Reescrito completo |

**Decisión: un fallo de la bitácora NO bloquea entrar ni salir.** Es lo contrario de `requirePermission`, y la diferencia no es de criterio sino de regla: RN-ACC-04 enumera las acciones sensibles y entrar al sistema no está entre ellas. Convertir una caída del log en imposibilidad de iniciar sesión transformaría un problema de registro en una caída total. Hay tests que fijan las dos conductas.

| Hallazgo | Impacto |

```ts
const attempts = new Map<string, { count: number; resetAt: Date }>()

export function checkRateLimit(key: string, max = 5, windowMs = 15 * 60 * 1000): void {
  const now = Date.now()
  const record = attempts.get(key)
  if (!record || record.resetAt < new Date(now)) {
    attempts.set(key, { count: 1, resetAt: new Date(now + windowMs) })
    return
  }
  if (record.count >= max) {
    throw new Error('RATE_LIMITED')
  }
  record.count++
}

    attempts.set(key, { count: 1, resetAt: new Date(now + windowMs) })

  }
  record.count++
}
```

```ts
import { randomBytes } from 'crypto'
import { eq, and, isNull, gt } from 'drizzle-orm'
import { db } from '@/db/client'
import { users, passwordResets } from '@/db/schema'
import { hash as argonHash } from '@node-rs/argon2'
import { sendPasswordResetEmail } from './email'

const RESET_EXPIRY_MS = 60 * 60 * 1000 // 1 hour

export async function requestPasswordReset(email: string, webBaseUrl: string): Promise<void> {
  const [user] = await db.select().from(users).where(eq(users.email, email)).limit(1)
  if (!user) return // Don't reveal whether email exists

  const token = randomBytes(32).toString('hex')
  await db.insert(passwordResets).values({
    token,
    userId: user.id,
    expiresAt: new Date(Date.now() + RESET_EXPIRY_MS),
  })

  const resetUrl = `${webBaseUrl}/reset-password?token=${token}`
  await sendPasswordResetEmail({ to: user.email, resetUrl, userName: user.name })
}

export async function resetPassword(token: string, newPassword: string): Promise<void> {
  const [reset] = await db
    .select()
    .from(passwordResets)
    .where(and(
      eq(passwordResets.token, token),
      isNull(passwordResets.usedAt),
      gt(passwordResets.expiresAt, new Date()),
    ))
    .limit(1)

  if (!reset) throw new Error('INVALID_TOKEN')

  const passwordHash = await argonHash(newPassword)
  await db.update(users)
    .set({ passwordHash, mustChangePassword: false })
    .where(eq(users.id, reset.userId))
  await db.update(passwordResets)
    .set({ usedAt: new Date() })
    .where(eq(passwordResets.token, token))

  await db.delete(db.$with('sessions').as(db.select().from(/* invalidates all user sessions */)))
}

export async function changePassword(userId: string, newPassword: string): Promise<void> {
  const passwordHash = await argonHash(newPassword)
  await db.update(users)
    .set({ passwordHash, mustChangePassword: false })
    .where(eq(users.id, userId))
}
```

```ts
import { and, eq, gte, lte, lt, sql } from 'drizzle-orm'
import { db } from '@/db/client'
import { auditLog } from '@/db/schema'

export interface AuditFilter {
  userId?: string
  action?: string
  resource?: string
  from?: Date
  to?: Date
  cursor?: number
  limit?: number
}

export async function queryAudit(filter: AuditFilter) {
  const where = and(
    filter.userId ? eq(auditLog.userId, filter.userId) : undefined,
    filter.action ? eq(auditLog.action, filter.action) : undefined,
    filter.resource ? eq(auditLog.resource, filter.resource) : undefined,
    filter.from ? gte(auditLog.createdAt, filter.from) : undefined,
    filter.to ? lte(auditLog.createdAt, filter.to) : undefined,
    filter.cursor ? lt(auditLog.id, filter.cursor) : undefined,
  )

  const rows = await db
    .select()
    .from(auditLog)
    .where(where)
    .orderBy(sql`${auditLog.id} DESC`)
    .limit(filter.limit ?? 50)

  return {
    rows,
    nextCursor: rows.length > 0 ? rows[rows.length - 1].id : null,
  }
}
```

```ts
import { cookies, headers } from 'next/headers'
import { ApiError } from './errors'

const API_URL = process.env.API_INTERNAL_URL!

export async function apiServerFetch<T>(
  path: string,
  init: RequestInit = {},
): Promise<T> {
  const cookieStore = await cookies()
  const headerStore = await headers()

  const res = await fetch(`${API_URL}${path}`, {
    ...init,
    headers: {
      ...init.headers,
      Cookie: cookieStore.toString(),
      'x-request-id': headerStore.get('x-request-id') ?? crypto.randomUUID(),
    },
    cache: init.cache ?? 'no-store',
  })

  if (!res.ok) {
    throw new ApiError(res.status, await res.text())
  }
  return res.json()
}

export async function getServerUser(): Promise<{ id: string; roles: string[] } | null> {
  try {
    return await apiServerFetch(AUTH_ME_PATH) // '/auth/me' — ver notas de Task 10
  } catch (e) {
    if (e instanceof ApiError && e.status === 401) return null
    throw e
  }
}
```

```ts
import { redirect } from 'next/navigation'
import { cookies } from 'next/headers'

const API_URL = process.env.API_INTERNAL_URL!

export async function loginAction(formData: FormData) {
  const email = formData.get('email') as string
  const password = formData.get('password') as string

  const res = await fetch(`${API_URL}/api/auth/sign-in/email`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password }),
  })

  if (!res.ok) {
    return { error: 'Credenciales inválidas' }
  }

  const setCookie = res.headers.get('set-cookie')
  if (setCookie) {
    const cookieStore = await cookies()
    const match = /aquazaku_session=([^;]+)/.exec(setCookie)
    if (match) {
      cookieStore.set('aquazaku_session', match[1], {
        httpOnly: true,
        sameSite: 'lax',
        secure: process.env.NODE_ENV === 'production',
        path: '/',
        maxAge: 60 * 60 * 24 * 7,
      })
    }
  }

  redirect('/dashboard')
}
```

- [ ] **Step 1: Write `api/drizzle/seed.ts`**

```ts
import { drizzle } from 'drizzle-orm/postgres-js'
import postgres from 'postgres'
import { eq } from 'drizzle-orm'
import { hash as argonHash } from '@node-rs/argon2'
import * as schema from '../src/db/schema'

const { users, roles, userRoles } = schema

async function main() {
  if (process.env.NODE_ENV === 'production' && process.env.SEED_CONFIRM !== 'yes') {
    console.error('ERROR: refusing to seed in production without SEED_CONFIRM=yes')
    process.exit(1)
  }

  const db = drizzle(postgres(process.env.DATABASE_URL!), { schema })

  // Check if any admin already exists
  const existingAdmins = await db
    .select({ name: roles.name })
    .from(roles)
    .innerJoin(userRoles, eq(userRoles.roleName, roles.name))
    .where(eq(roles.name, 'admin'))
    .limit(1)

  if (existingAdmins.length > 0) {
    console.error('ERROR: admin already exists. Refusing to seed.')
    process.exit(1)
  }

  // Insert the 4 roles
  await db.insert(roles).values([
    { name: 'admin', description: 'Administrador del sistema' },
    { name: 'seller', description: 'Vendedor de ruta' },
    { name: 'pos', description: 'Punto de venta fijo' },
    { name: 'contador', description: 'Contador externo (read-only)' },
  ]).onConflictDoNothing()

  // Create the first admin
  const email = process.env.SEED_ADMIN_EMAIL ?? 'admin@aquazaku.com'
  const name = process.env.SEED_ADMIN_NAME ?? 'Admin Inicial'
  const password = process.env.SEED_ADMIN_PASSWORD

  if (!password) {
    console.error('ERROR: SEED_ADMIN_PASSWORD is required')
    process.exit(1)
  }

  const passwordHash = await argonHash(password)
  const [admin] = await db.insert(users).values({
    email, name, passwordHash,
  }).returning({ id: users.id })

  await db.insert(userRoles).values({ userId: admin.id, roleName: 'admin' })

  console.log(`✓ Seed complete. Admin: ${email}`)
  process.exit(0)
}

main().catch((e) => { console.error(e); process.exit(1) })
```

- [ ] **Step 3: Write E2E smoke test `api/src/__tests__/e2e.test.ts`**

```ts
import { describe, expect, it, beforeAll, afterAll } from 'vitest'
import Fastify from 'fastify'
import cookie from '@fastify/cookie'
import { authRoutes } from '@/modules/auth/routes'
import { userRoutes } from '@/modules/users/routes'
import { auditRoutes } from '@/modules/audit/routes'
import { hash as argonHash } from '@node-rs/argon2'
import { db } from '@/db/client'
import { users, userRoles, roles } from '@/db/schema'
import { eq } from 'drizzle-orm'

describe('M0 E2E smoke', () => {
  const app = Fastify()
  let adminId: string
  let sessionId: string

  beforeAll(async () => {
    await app.register(cookie)
    await authRoutes(app)
    await userRoutes(app)
    await auditRoutes(app)
    await app.ready()

    // Seed an admin for the test
    await db.insert(roles).values({ name: 'admin', description: 'admin' }).onConflictDoNothing()
    const passwordHash = await argonHash('test1234')
    const [admin] = await db.insert(users).values({
      email: 'e2e-admin@test.com', name: 'E2E Admin', passwordHash,
    }).returning({ id: users.id })
    adminId = admin.id
    await db.insert(userRoles).values({ userId: adminId, roleName: 'admin' })
  })

  afterAll(async () => {
    await app.close()
  })

  it('admin can sign in and access /audit', async () => {
    // Sign in (call Better-Auth handler directly)
    const signInRes = await app.inject({
      method: 'POST',
      url: '/api/auth/sign-in/email',
      payload: { email: 'e2e-admin@test.com', password: 'test1234' },
    })
    expect(signInRes.statusCode).toBe(200)
    const cookieHeader = signInRes.headers['set-cookie']
    expect(cookieHeader).toBeDefined()

    // Extract session cookie
    const match = /aquazaku_session=([^;]+)/.exec(cookieHeader as string)
    sessionId = match![1]

    // Call /auth/me
    const meRes = await app.inject({
      method: 'GET',
      url: '/auth/me',
      headers: { Cookie: `aquazaku_session=${sessionId}` },
    })
    expect(meRes.statusCode).toBe(200)
    expect(meRes.json().roles).toContain('admin')

    // Call /audit (admin permission)
    const auditRes = await app.inject({
      method: 'GET',
      url: '/audit',
      headers: { Cookie: `aquazaku_session=${sessionId}` },
    })
    expect(auditRes.statusCode).toBe(200)
  })

  it('unauthenticated request to /audit returns 401', async () => {
    const res = await app.inject({ method: 'GET', url: '/audit' })
    expect(res.statusCode).toBe(401)
  })
})
```
